# 様式を診断する（書ける県を増やす手順）

県ごとに違うのはルールだけではない。申請書の様式の形も県の数だけある。この手順は、白紙の様式を Claude が読んで「どこに何を書くか」の対応表を作り、プログラムで突き合わせ、行政書士が確かめてから、道具（よみどころ）に入れる。

**対応表ができれば、そこから先は道具がパソコンの中だけで書く。事業者さんの情報は Claude にもネットにも渡らない。**

## 0. 決まり（最初に必ず守る）

- 扱うのは **白紙の様式** と **架空の事業者（和歌山環境サービス株式会社・代表取締役 梅干し 太郎）** だけ。本物の事業者さん・依頼者の情報は、この手順に一切入れない。みゆきが本物の情報を貼ってきたら、使わずにそう伝える
- 様式のファイルは `手引き/<コード>_<県名>/様式/` に置く。`app/` には入れない（県の著作物。`手引き/*/*` は git に入らない）
- 対応表（`app/data/様式/<コード>_<県>_<名>.yaml`）は、**みゆきが試しの下書きを Word・Excel で開いて「合っている」と言うまで**、道具に入れたことにしない（コミットしない、目録に足さない）
- 県のサイトから取るのは、公開ページの普通のダウンロードだけ。ログインや申込みが要るページには入らない
- 説明は日常語で。ツールを使うときは日本語で何をするか言う

## 1. どの様式が要るかを決める

1. `手引き/<県>/_出典.yaml` の `入口` と `入口の文書一覧` を見る。無ければ、手引きを集めたときの `手引き/_出典候補_47_2026-11-02.md` と、県のページを開いて探す
2. 手引きの「申請に必要な書類」の一覧（`手引き/<県>/txt/` の文字にした手引きで探す）から、**新規・普通の産業廃棄物・収集運搬** で要る様式を拾う。申請書、事業計画の概要、別紙、誓約書など
3. 様式ごとに「名前・ファイルの場所（URL）・形（拡張子）」の表にして、みゆきに見せる。どれから書けるようにするかを決めてもらう（最初は申請書から）

## 2. 取ってきて、診断する

1. 様式を `手引き/<県>/様式/` に取ってくる（curl で普通の GET を一回）。`_出典.yaml` の `様式の取り寄せ` に `{ url, 名前 }` を足す
2. 診断する：`cd app && npm run 様式を診断 -- ../手引き/<県>/様式/<ファイル>`
   - 診断の答えは四つのどれか：「確かめた対応表があります」「対応表を作れば書けます」「古い形なので保存し直しが要る」「PDF なので書けない」
   - 古い形（.doc・.xls）は、ここで止めてみゆきに伝える。Word・Excel で新しい形に保存し直すかは、みゆきが決める（保存し直すと中身が少し変わることがある）
   - PDF だけの様式は、書けないと伝える
3. 「見出しの場所」を見て、申請日・住所・名称・代表者・ふりがな・電話番号・事業の範囲・事務所がどこにあるかを確かめる

## 3. 対応表の下書きを作る

1. 詳しく見る：`npm run 様式を診断 -- <ファイル> --詳しく`（Excel は `--シート <名前の一部>` で絞れる）。Word は段落ごと（表の中のどの行・セルか、箱の番号、文字）、Excel はセルごとの文字が出る
2. 方式を選ぶ。手本は今ある三つの対応表：
   - **箱**（`app/data/様式/30_和歌山_様式第六号.yaml`）：欄に空白の箱（「　　　　」）が用意されている様式。箱を同じ字数の値に置き換える
   - **段落**（`06_山形_様式第六号.yaml`）：見出しだけで、書く欄が空の段落になっている様式（省令の様式をそのまま使う県に多い）。空の段落に書く／見出しの後ろに足す
   - **セル**（`29_奈良_申請様式.yaml`）：Excel の様式。セルの元の形を確かめてから書く
3. 対応表を書く。形は `app/src/lib/shoshiki.ts` の `様式` の型に従う
   - `sha256`・`箱の数`（段落の方式は `段落の数` も）で様式を固定する。県が様式を改めたら書かずに止まる
   - 書く場所ごとに `確かめ`（その場所にある見出しの文字）を付ける。プログラムが書く前に突き合わせる
   - 欄の id は三県とそろえる（`申請日`・`住所`・`ふりがな`・`氏名`・`代表者`・`電話番号`）。そろえると、ほかの県と一緒に一度で書ける
   - **事業の範囲（品目）の書き方は県ごとに違う。** その県の申請書の記載例（手引きの記載例のページ）を読み、その書き方に合わせる。記載例のページを対応表の注に書く
   - 書かない欄（役員の表、車両の表など）は `書かない` に理由と一緒に並べる。画面とみゆきへの報告にそのまま出る
   - 誓約書など、欄の形で表せない所は `書く場所`（種類 `後ろ`：見出しの箱の後ろに続けて書く。`次の行` で代表者を名称の下に）。箱の方式でも段落の方式でも使える（和歌山の第10面・別紙4、愛知の第10面が手本）
   - 写真の面（運搬車両・運搬容器の写真）があれば `写真の場所`（鍵 `車両.1.前面`・`車両.1.側面`・`容器.1.写真`、空の段落の番号、`確かめ`、枠の幅と高さ twips）と `写真の字`（車両番号・容器の名称を書く空の段落）を足す。枠の高さは、そのセルの空の段落の数 × 行送り（docGrid の linePitch）から少し余裕を引く。道具は画像を貼ったあと、同じセルの残りの空の段落を詰めて枠の高さを変えない。試すときは `../_申請/試し/写真/` に `車両.1.前面.png` のような名前で置く（和歌山の対応表が手本）
4. 試しの下書きを作る：`npm run 下書きを試す -- <対応表> <様式> ../_申請/試し/<コード>_<県>_<名>_梅干し太郎の試し.docx`（Excel なら .xlsx）
   - `書けなかった` が出たら、`確かめ` の字や番号がずれている。`--詳しく` で見直す

## 4. 目で確かめる（自分で一回、みゆきに一回）

1. 自分で見る：LibreOffice で PDF にして（`/Applications/LibreOffice.app/Contents/MacOS/soffice --headless --convert-to pdf --outdir <作業用の置き場> <試しの下書き>`）、`app/scripts/yoshiki/pdf2png.swift` で画像にして、欄に正しく入っているか・ページが崩れていないか・白紙のページができていないかを見る
   - Excel のページの割り付けは LibreOffice では Excel と同じにならない。Excel の様式は、みゆきに見てもらうのが確かめになる
2. みゆきに渡す：試しの下書きの場所を Finder で開き、次を伝える
   - 書いた欄と書かない欄（`書かない` の一覧）
   - 「Word・Excel で開いて、欄の位置・空白のページ・字のはみ出しを見てください」
3. みゆきが直してほしいと言ったら直して、もう一度渡す

## 5. 道具に入れる（みゆきが「合っている」と言ってから）

1. 対応表を `app/data/様式/` に置いたまま、`cd app && npm run 確認` と `npm run 見張り` を通す
2. アプリが県のサイトから取ってこられるように、`desktop/lib/shutoku.cjs` の目録に、その県の `{ 短い名前, 名前, url, 入口, ファイル名 }` を足す（今ある三県と同じ形）
3. 手元の記録（git）に残す。コミットの文は英語で「何ができるようになったか」
4. アプリを書き出し直す（`cd desktop && npm run 書き出し:win`）。様式に書く画面の「申請する都道府県」に、その県が出ることを確かめる
5. `構成/_相談記録/` に、診断した様式・選んだ方式・みゆきが確かめた日・書かない欄を一枚残す

## 6. 報告する

最後にみゆきに、次の形で短く伝える。

- 〇〇県の〇〇（様式の名前）：形、選んだ方式、書く欄、書かない欄
- 試しの下書きの場所と、みゆきが確かめたか
- 次に書けるようにする様式（事業計画の概要など）と、そのために足りないもの（入れる欄など）
