# 書き方を読む（事業計画の概要の型を作る手順）

申請書の様式が県の数だけあるように、事業計画の概要の**書き方**も県の数だけある。同じ「性状」でも、固形状と書けば足りる県と、どんな物かを具体的に書かせる県がある。この手順は、県の記載例を Claude が読んで文の組み立てを「書き方の型」にし、行政書士が確かめてから道具に入れる。

**型ができれば、そこから先は道具がパソコンの中だけで差し込む。事業者さんの話は Claude にもネットにも渡らない。**

スキル「様式を診断する」（`.claude/skills/yoshiki-shindan/SKILL.md`）と対になる。向こうは「どこに書くか」、こちらは「何をどう書くか」。

## 0. 決まり（最初に必ず守る）

- 読むのは **県の公開の手引き・記載例・白紙の様式** だけ。本物の事業者さん・依頼者の情報は一切入れない。試しは架空の事業者（和歌山環境サービス株式会社・代表取締役 梅干し 太郎）だけ
- **道具は数字や事実を作らない。** 記載例の数字（運搬量 20 t/月、従業員 22 人など）は型の文に入れない。「例」にだけ書く。聞いていない空きは「【要確認：見出し】」を残す
- 空きの名前（差し込み口の id）は `app/data/書き方の型/_共通の差し込み口.yaml` にそろえる。同じ意味の空きに県ごとに別の名前を付けない（名簿に一度入れれば全部の県で使える、が崩れる）。その県だけの空きは、id の頭に県コードを付けて足す（例：`23_自動車等破砕物`）
- 型は **みゆきが試しの下書きを Word・Excel で見て「合っている」と言うまで** 道具に入れたことにしない（コミットしない）
- 県のサイトから取るのは公開ページの普通のダウンロードだけ。自動の取得を断るサイト（愛知）はくぐり抜けず、みゆきに手で保存してもらう
- 説明は日常語で。ツールを使うときは日本語で何をするか言う

## この手順の位置（2026-11-06 から）

この手順は、スキル「様式を診断する」の 3 の中から呼ばれる。先に診断の 2 で **分析表**（`app/data/様式/<コード>_<県>_分析.md`）ができていて、そこに「概要の文の形」（全体計画・具体的な計画・環境保全の組み立て、品目の書き方、名前の言い換え）が記載例からの引用つきで書いてある。型はその分析表から作る。分析表が無い、または記載例が手元に無いなら、型を書き始めずに診断の 1 に戻る。

型は **三つの欄（全体計画・具体的な計画・環境保全）を全部** 作る。一つだけ作って残りを「あとで」にしない。愛知で、概要の文を後回しにして直しが増えた。

## 1. 記載例をそろえる

1. `手引き/<コード>_<県名>/_出典.yaml` の `入口の文書一覧` と `ファイル` を見る。事業計画の概要の記載例が、手引きの中にある県（山形：`shuun_tebiki_all.pdf` の記載例の章）と、面ごとの別の PDF の県（奈良）がある
2. 手元に無ければ取ってくる（curl で普通の GET を一回）。`_出典.yaml` に `記載例の取り寄せ: [{ url, 名前 }]` を足す。本体は `手引き/<県>/記載例/` に置く（git に入らない）
3. PDF を文字にする：`app/scripts/yoshiki/pdftext.swift`（`swiftc -O pdftext.swift -o <作業用の置き場>/pdftext` のあと `pdftext <PDF> 手引き/<県>/txt/<ファイル名>.txt`）。`scripts/tebiki/to_text.py` は pymupdf が無いと動かない
4. 文字にしたものから、次の場所を探して行番号を控える：**１．事業の全体計画／２．品目の表（運搬量・性状・排出事業場・運搬先）／３．運搬施設（車両・容器）／４．収集運搬業務の具体的な計画／５．環境保全措置の概要**
5. 地図の記録も見る：その県の観点「事業計画概要」「排出事業者」「運搬先」「性状」の記録（`cd app && npm run 確認` が読む記録。画面では県のページのカード）に、手引きの出典ページが付いている。そのページに県独自の決まりがある

## 2. 読んで、共通と独自に分ける

記載例の文を読みながら、次の表を作る（みゆきへの報告にそのまま使う）。

| 欄 | 記載例の文の組み立て | 共通の空き | その県だけの決まり | 出典 |
|---|---|---|---|---|
| 全体計画 | 一つの文章か、品目ごとの箇条書きか。営業範囲を書くか | 排出元・品目の言い方・運搬先・営業範囲 | 例：山形は「排出事業者との契約に基づき…車両…を用いて収集運搬し、排出事業者の指定する処分施設等に搬入する」 | 手引き pNN |
| 品目の表 | 一品目一行か。石綿の「含む・除く」で行を分けるか。水銀使用製品を一行にまとめるか | 品目ごとの運搬（運搬量・性状・排出元・運搬先） | 例：山形「特定できない場合は県内一円事業場等でも可」 | |
| 具体的な計画 | 番号付きの項目か、箇条書きか。何を書かせるか | 車両・時間・休業日 | | |
| 環境保全 | (1)(2) を一つのマスに書くか、別のマスか。飛散流出・悪臭・騒音の項目 | 石綿の容器・水銀使用製品の容器 | | |

- 手引きの余白の注意書き（「車検証の『車体の形状』の欄を記入」「建設現場など具体的に記載し、特定できない場合は県内一円事業場等でも可」）は、その県の決まりそのもの。空きの `注` に写す
- 記載例に無い項目（積替保管ありの例が無い、など）は、作らずに「【要確認：…】」の行にする

## 3. 型を書く

1. 手本は `app/data/書き方の型/30_和歌山_様式第六号.yaml`。形は `app/src/lib/shoshiki.ts` の `書き方の型`・`差し込み口`・`型の行`（526〜600行あたり）に従う
2. `sha256` は **文を書き込む様式のもの**（申請書と別の Word なら、別の Word の sha。`npm run 様式を診断 -- <様式>` が出す）。様式が違えば道具は書かずに止まる
3. `差し込み口` は共通の一覧から同じ id・同じ見出しで写す。使わない口は入れない。県独自の口は県コードを頭に付けて足す
4. `欄` の id は、様式の対応表の `文の欄` の id と同じにする（共通の一覧の「欄の名前」。マスが分かれている県は `環境保全_運搬`・`環境保全_積替保管`）
5. 行ごとに `出典`（資料とページ）と `写し`（まま／一部／組み替え／なし）を付ける。これが「道具が作った文ではなく、県の記載例に沿った文」の証拠になる
6. 条件（石綿あり・水銀使用製品あり・積替保管無…）は `型の条件` にあるものだけ使う
7. 一つの欄に書き方が二つあるなら `形` にする（和歌山の「記載例の形」と「品目ごとの箇条書き」）。最初の形は県の記載例の形

## 4. 様式につなぐ（様式を診断する、の手順で）

1. 対応表（`app/data/様式/<コード>_<県>_<名>.yaml`）に `文の欄` を足す：`見出しの箱`・`見出しの字`・`空の段落`・`書く行`・`一行の字数`・`次の箱`・`次の字`。空の段落の数は `--詳しく` で数える（違うと道具は書かない）
2. 品目の表は `書く場所` に一行ずつ。値は `{品目表.N}`・`{品目表.N.運搬量}`・`{品目表.N.性状}`・`{品目表.N.排出元}`・`{品目表.N.運搬先}`（品目ごとの口の項目の id）
3. 一行の字数は、記載例の折り返しとマスの幅（twips ÷ 字の大きさ）から取り、少し控えめにする（はみ出すと行が増えて表が次のページへ押し出される）

## 5. 試して、確かめてもらう

1. `cd app && npm run 下書きを試す -- <対応表> <様式> ../_申請/試し/<コード>_<県>_<名>_梅干し太郎の試し.docx`。試しの値は `app/scripts/shitagaki-tameshi.ts` にある（型の空きの試しの値もここ）
2. LibreOffice で PDF にして `app/scripts/yoshiki/pdf2png.swift` で見る。行がはみ出していないか、表が次のページへ押し出されていないか
3. みゆきに渡す：試しの場所、書いた欄、【要確認】を残した所、県独自の決まり（2 の表）

## 6. 報告する

- 〇〇県の事業計画の概要：記載例の場所、共通の空きで足りた所、県独自に足した空き、【要確認】のまま残る所
- 試しの下書きの場所と、みゆきが確かめたか
- 次の県に回すときに効くこと（この県で初めて出た決まり。共通の一覧に足すべき口があれば、その案）
