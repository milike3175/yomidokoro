# 次の設計：許認可を増やし、行政書士の経験を貯めていく道具にする

2026-11-07 ジョブズ。みゆきの言葉：「行政書士がこのツールを使って自分の調べたことを貯めていける。経験が増えるごとに、ここにも情報が貯まっていく。そんなアプリにしたい」「新しい許認可をポチッと押したら、その申請に必要な情報を入力する欄が同じようにでき、その許認可専用の地図もできる」。

これは実装の前の設計。ハッカソンの提出（11/8）には入れない。産廃の収集運搬で作った部品を、許認可を引数にして回す形にする。**新しく発明する部品は無い。** 下に「今ある部品」と「足す部品」を分けて書く。

## 1. 使う人の一日（できあがりの姿）

1. 行政書士が「新しい許認可」を押し、許認可の名前（例：古物商許可）と自治体（例：和歌山県）を入れる
2. 道具が公式サイトから手引き・案内・様式を探して読み、共通の観点 12 項目と、その許認可だけの観点を出典つきで一枚にする（今の「はじめての許認可」）
3. 「この許認可の地図を作る」を押すと、その許認可の観点の一覧が提案される。行政書士が削って決める
4. 道具が 47 自治体ぶんの手引きを探して読み、地図にする（手引きの層）
5. 「この県の申請書も書けるようにする」を押すと、様式と記載例を取ってきて対応表と型を作り、画面に入力欄が出る（様式の層）
6. 電話で聞いたこと・補正で言われたこと・受理された実績は、電話メモの取込で手帳に貯まる。地図のカードに「電話」「補正」「受理実績」の札で並び、手引きと食い違えば「揺れあり」になる（手帳の層）
7. 年に一度、手引きの改訂と記録の古さで「再確認」の印が付く。電話で確かめると消える
8. 支部や同業者に渡したいときは「共有に出す」で、担当者の名前と案件を外した形で出す

**貯まっていくのは三つ。** 手引きの層（辞書。配れる）、様式の層（対応表と型。配れる）、手帳の層（自分の経験。手元だけ。名前を外せば配れる）。許認可が増えるほど辞書と様式が増え、年数が増えるほど手帳が厚くなる。

## 2. 置き場（許認可を引数にする）

今は `産廃収集運搬` が固定で、データの置き場と画面の両方に埋まっている。これを許認可ごとのフォルダにする。

```
app/data/
  許認可.yaml                       … 許認可の一覧（id、名前、所管の法律、許可権者の単位、状態）
  <許認可id>/
    観点.yaml                       … その許認可の観点（番号・id・群・表示名・手引きで探すもの・電話で聞く文・品目で変わる）
    品目.yaml                       … 品目や区分がある許認可だけ（産廃の品目、建設業の業種など）
    <コード>_<自治体>/手引き.yaml    … 手引きの層（今の 産廃収集運搬/30_和歌山県/手引き.yaml と同じ形）
    <コード>_<自治体>/受理実績.yaml
    様式/<コード>_<自治体>_<名>.yaml … 対応表
    書き方の型/<コード>_<自治体>_<名>.yaml
    見本/                            … 公開版に載せる見本の電話（名前なし）
手引き/<許認可id>/<コード>_<自治体>/  … 公開資料の本体（git に入れない）
手帳/<許認可id>/<コード>_<自治体>/電話/  … 自分の電話・補正の記録（手元だけ）
```

今の `産廃収集運搬` はそのまま最初の許認可になる（`app/data/産廃収集運搬/` を `app/data/sanpai_shushu/`… にはしない。id は日本語のままでよい。すでに `手帳/産廃収集運搬/` がこの形）。

**許可権者の単位** は許認可で違う（産廃は都道府県と政令市、建設業は都道府県と国の地方整備局、古物商は警察署）。`許認可.yaml` に「単位：都道府県／都道府県＋政令市／警察署／市区町村」を持ち、地図の描き方（47 の地図か、一覧か）をそれで切り替える。

## 3. 画面（地図と入力欄を許認可ごとに）

- トップ：許認可を選ぶ帯（産廃収集運搬／建設業許可／…／新しい許認可）。選ぶと、その許認可の地図（47 の地図か一覧）、府県くらべ、申請書に下書きする、名簿、が切り替わる。URL は `/<許認可id>/<コード>/`
- 県ページ：観点の群と番号は `観点.yaml` から出る。今の画面のまま（観点を探す、記録のあるものだけ、目次、チェックリスト、補正）
- 申請書に下書きする：対応表と型があれば、入力欄は今の仕組みで自動に出る（`様式が使う口`・`使う口`）。無い県は「この県も書けるようにする」のボタン
- はじめての許認可：今の一覧に「地図にする」「申請書を書けるようにする」の二つのボタンを足す
- 名簿：事業者さんは許認可をまたいで一つ。許認可ごとの欄（品目、業種）は `品目.yaml` から出る

## 4. ボタンの裏（Claude をどこで呼ぶか）

公開版は鍵を持たない静的なサイト、アプリ版は Claude を呼ばない。これは変えない（事業者さんの情報を外に出さない線）。Claude が要る作業は、**Claude Code を入れたパソコンで、スキルとして**動く。

- ボタンは、スキルを呼ぶ一行（`claude -p "〇〇県の古物商許可の申請書も書けるようにして"`）を作って、クリップボードに写すか、アプリから `claude` を起動する。運営に `claude -p` の扱いを確かめてから（README 次にやること 3）
- 鍵は `app/.env` にだけ。公開版・アプリ版に鍵は入らない

### スキルの一覧（今あるもの＋足すもの）

| 段 | スキル | 今 | 足すこと |
|---|---|---|---|
| 下調べ | `npm run 探す` → `npm run はじめて読む` | ある（端末） | スキル化（hajimete-shiraberu）。許認可名と自治体を引数に |
| 観点づくり | （無い） | 産廃は人が 32 項目を作った | **kanten-tsukuru**：共通 12 項目＋下調べで出た独自の観点を、数自治体ぶん見比べて提案。行政書士が削る。`観点.yaml` を書く |
| 手引きの層 | `npm run 取得`・`npm run 読む`（産廃固定） | ある | 許認可を引数に。出典候補の一覧（`_出典候補_47.md`）も許認可ごとに Claude が探す（下調べの「探す」を 47 回） |
| 様式の層 | `yoshiki-shindan`・`kakikata-yomu` | ある | 許認可を引数に。品目の書き方の部品（印・札・文・セル）は許認可の品目に依らない形にする |
| 手帳の層 | `denwa-memo`・`npm run 取込` | ある | 観点の一覧を許認可で切り替えるだけ |
| 揺れ・再確認 | `npm run 判定`・再確認の印 | ある | 許認可を引数に |

## 5. 経験が貯まる仕組み（手帳の層を厚くする）

- 記録の種別は今の五つのまま：手引きに明記／電話／補正／受理実績／同業者。どれも観点に結びつく
- **受理実績** を取込で入れられるようにする（今は YAML を手で書く）。「〇〇県で、この書き方で受理された」が、次の申請の根拠になる
- **案件から学ぶ**：申請書を作成した日と県・品目を名簿に残す。受理されたら「受理実績に入れる」を押すと、その作成の内容（品目の書き方・運搬先の書き方）が受理実績の記録になる。事業者名は入れない
- **揺れの解消**：電話で確かめた答えで揺れが解消したら「確かめ済み」の印（今ある）。古い記録は消さず、履歴として残す
- **再確認**：手引きの改訂検知（sha256）と 1 年経過（今ある）。許認可ごとに改訂の多い所（手数料・様式）を優先して知らせる
- **共有に出す**（今ある）：手元だけの欄を外した形。支部に渡す・同業者の手帳と突き合わせる、の入口

## 6. 作る順（提出後）

1. 置き場を許認可ごとにする（`許認可.yaml`、画面の URL、取得・読む・判定の引数）。産廃は動いたまま
2. 「はじめて」をスキル化し、独自の観点から `観点.yaml` を提案する kanten-tsukuru を作る。一つ目の試しは建設業許可（下調べ済み）
3. 建設業許可で 47 都道府県の手引きの層を回す（産廃で一週間かかった所。出典探しの自動化が鍵）
4. 建設業許可の様式を一県、yoshiki-shindan で診断して入力欄が出ることを確かめる
5. 受理実績の取込と「案件から学ぶ」
6. アプリのボタンからスキルを呼ぶ

一つ目の許認可（建設業許可）で 1〜4 が通れば、三つ目からは人の作業は「観点を削る」「記載例を落とす」「Word で確かめる」だけになる。

## 7. 変えない線

- 事業者さんの情報は Claude にもネットにも送らない。様式への記入は手元のプログラムだけ
- 共有する記録に担当者の個人名を残さない。手帳の「手元だけ」の欄には残してよい
- 道具は判断しない。揺れは「揺れあり、要確認」で止め、判断は行政書士
- 引用は本文と照合する。Claude の引用を Claude に確かめさせない
